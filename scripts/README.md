# Skripte

- `npm run generate:icons` erzeugt aus `app-icon.svg` die macOS-, Windows- und Linux-App-Icons in `packages/gui/resources`.
- Updates werden ausschließlich über den `github`-Provider von `electron-updater` verteilt. `npm run release:mac`, `npm run release:mac-intel` und `npm run release:win` bauen mit `electron-builder --publish always` und laden die Artefakte direkt in das GitHub Release des aktuellen Tags hoch. Dafür muss `GH_TOKEN` (z. B. `export GH_TOKEN=$(gh auth token)`) mit `repo`-Rechten gesetzt sein, bevor die Skripte laufen.
- `npm run release:stage:linux` organisiert die von GitHub Actions gebauten Linux-Artefakte lokal unter `packages/gui/release/v<Version>/linux-x64`; ein Website-Transport findet nicht mehr statt.
- `npm run release:tag` prüft den sauberen Git-Stand, erstellt aus der GUI-Version den annotierten Tag `v<Version>` und pusht ihn. Dadurch startet der Linux-Release auf GitHub Actions. `npm run release:tag:dry` zeigt den geplanten Schritt ohne Git-Änderung. `--allow-dirty` ist nur für bekannte, nicht zu committende lokale Änderungen vorgesehen.
- `npm run release:patch`, `npm run release:minor` und `npm run release:major` erhöhen die GUI-Version, aktualisieren das Lockfile, committen die Versionsdateien und starten über den Tag den Linux-Release auf GitHub Actions. Der lokale macOS-Release muss danach separat mit `npm run release:mac` gestartet werden. Mit `-- --dry-run` lassen sich die Schritte vorab anzeigen.
